הריכוז הזה הוא החלטת אבטחה: קל לשכוח בדיקה כשהיא משוכפלת בעשרה מקומות.
כל endpoint שנוגע במטופל, בבדיקה, בהתראה או בדוח קורא לאחת מהן.

**סדר הבדיקות.** ב-`create_test` ההרשאה נבדקת לפני אימות הקלט. אחרת משתמש
בלי הרשאה היה יכול ללמוד ממסרי השגיאה אם מספר בדיקה או מעבדה קיימים —
דליפת מידע דרך הודעות שגיאה.

**הממשק אינו שכבת אבטחה.** הסתרת פריטי תפריט וכפתורים לפי תפקיד היא נוחות
בלבד. ניסיון גישה ישיר דרך כתובת URL נחסם בשרת ומחזיר 403 עם הודעה בעברית.

## אימות משתמשים

| רכיב | מימוש |
|---|---|
| סיסמאות | Argon2 (`argon2-cffi`) |
| Access token | JWT, HS256, תוקף 30 דקות |
| Refresh token | JWT נפרד עם `type=refresh`, תוקף 7 ימים |
| הפרדת סוגי טוקן | `decode_token` דוחה טוקן מסוג לא נכון |
| הגבלת קצב על התחברות | 10 בקשות לדקה לכתובת IP (`slowapi`) |
| הודעת כישלון | אחידה — לא מגלה אם הדוא״ל קיים |

## מידע מזהה — תעודת זהות

תעודת זהות ישראלית נחשבת מידע רגיש ומטופלת בשלוש שכבות:

1. **הצפנה** — `national_id_encrypted` ב-Fernet (AES-128-CBC + HMAC).
2. **HMAC לחיפוש** — `national_id_hash`, HMAC-SHA256 עם מפתח נפרד.
   מאפשר חיפוש ובדיקת כפילות בלי לפענח אף רשומה.
3. **הסתרה בתצוגה** — הממשק מקבל `*******34` בלבד; הערך המלא לא נשלח ללקוח.

בנוסף מיושמת בדיקת ספרת ביקורת מלאה (אלגוריתם Luhn הישראלי) ב-
`validate_israeli_id`, כדי לדחות מספרים שאינם תקינים.

**תעודת זהות מלאה לעולם לא נכתבת ל-log ולא ל-Audit.**

## Audit

הפעולות הנרשמות: התחברות, צפייה במטופל, יצירת מטופל, יצירת בדיקה, הרצת ניתוח,
שיוך וביטול שיוך רופא, יצירת משתמש, שינוי הגדרות מנהל, עדכון התראה, הורדת דוח.

הסינון קורה בכתיבה, ב-`AuditService.record`:

```python
SENSITIVE = {"password", "token", "national_id", "medical_record"}
```

מפתחות אלה מוסרים לפני השמירה. לשינויי הגדרות ושיוכים נשמרים `before` / `after`
כדי לאפשר מעקב אחר תיקונים.

## הגנות ברמת האפליקציה

| הגנה | מימוש |
|---|---|
| כותרות אבטחה | `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy` |
| CORS | רשימת מקורות סגורה מ-`.env`, שיטות מוגבלות |
| SQL Injection | SQLAlchemy ORM עם פרמטרים בלבד; אין SQL מחורז |
| אימות קלט | Pydantic v2 בכל endpoint, כולל `extra="forbid"` בניהול |
| שגיאות | תגובה מובנית `{code, message, details}`; אין stack trace ללקוח |
| גודל קובץ בייבוא | חסימה מעל 5MB |
| סודות | `.env` בלבד, מוחרג ב-`.gitignore`; `.env.example` ללא ערכים אמיתיים |

## מה חסר לפני שימוש אמיתי

זהו אב־טיפוס לימודי. לפני עבודה עם מידע רפואי אמיתי יידרשו:

- מערכת ניהול מפתחות (KMS) במקום מפתחות ב-`.env`
- אימות דו-שלבי (MFA) למשתמשי צוות
- רשימת ביטול ל-refresh tokens (כיום טוקן תקף עד לפקיעתו)
- הגבלת קצב מבוזרת (כיום בזיכרון התהליך)
- נעילת חשבון לאחר ניסיונות כושלים חוזרים
- HTTPS מאולץ ו-HSTS
- ניטור, התראות אבטחה, גיבוי והתאוששות
- בדיקות חדירה והתאמה לרגולציה הרלוונטית
