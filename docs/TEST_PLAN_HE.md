## הרצה

```bash
cd backend
pytest -q
```

```bash
cd frontend
npm test
npm run build
```

```bash
# E2E — דורש backend פעיל עם seed
cd backend && LOGIN_RATE_LIMIT=200/minute uvicorn app.main:app --port 8000
cd frontend && npx playwright install chromium && npx playwright test --workers=1
```

> ה-E2E מריץ יותר מ-10 התחברויות בדקה, ולכן דורש הרפיה של הגבלת הקצב דרך
> `LOGIN_RATE_LIMIT`. ברירת המחדל (`10/minute`) נשארת בתוקף בכל סביבה אחרת.
> יש להריץ עם `--workers=1` כדי שהתרחישים לא יתחרו על אותו מסד נתונים.

## תקלות שנמצאו ותוקנו במהלך הבדיקות

| מה נמצא | תיקון |
|---|---|
| ב-`create_test` אומת הקלט לפני ההרשאה — משתמש ללא הרשאה קיבל 422 שחשף אם מעבדה או מספר בדיקה קיימים | ההרשאה נבדקת ראשונה |
| תשובת 403 גרמה למסך לבן במקום להודעה — הבדיקה נעשתה לפני שהנתונים היו זמינים | בדיקת שגיאה לפני טעינה, ואי-רינדור בלי נתונים |
| TanStack Query ניסה שוב בקשות 4xx | 4xx אינו מנוסה מחדש — זו תשובה מכוונת |
| כפתור "יציאה" היה `absolute` בתוך סרגל `static`, ולכן נמתח כפס שקוף לרוחב תחתית כל עמוד ובלע לחיצות | הסרגל הפך ל-`sticky` ומשמש כמסגרת מיקום |
| כפתורי ההדגמה לא היו ניתנים לזיהוי חד-ערכי | נוסף `aria-label` ייעודי לכל כפתור |

## מה לא נבדק אוטומטית

- **ייצוג עברית ב-PDF** — נבדק שהקובץ תקין ונפתח; נכונות הכיווניות נבדקה ידנית.
  הגופן תלוי סביבה (Arial ב-Windows, DejaVu ב-Docker).
- **`docker compose up`** — הקובץ תקף (`docker compose config`), אך בנייה מלאה
  לא הורצה בסביבה זו.
- **נגישות** — יושמו תוויות, ניווט מקלדת, `aria-modal` ומצבי פוקוס.
  לא הורץ כלי בדיקה אוטומטי כמו axe.
- **עומס וביצועים** — לא נבדקו. יש עימוד ואינדקסים, אך ללא מדידה.
